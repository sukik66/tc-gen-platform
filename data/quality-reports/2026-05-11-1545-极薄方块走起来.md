## FAIL 详情

### ❌ F1. qc-1778609400002 — 移动管线（SR-2 FAIL）

**契约规则**：移动管线仅在非[存在]状态下产生有效位移

**违规证据**：
- `PlayerMovementPipeline.Tick()` 无 Idle 态位移抑制 guard
- Grep `PlayerState.Idle|Idle.*return|CanMove` → **0 命中**
- 代码流程：输入→位移计算→碰撞解算→位置更新→**状态评估**（末尾）
- 当 Idle 态收到 WASD 输入时，**位移先于状态转换**被应用

**影响评估**：低。实际表现为"按键当帧即移动即转 Walking"，单帧位移量极小（约 walkSpeed×dt ≈ 5×0.016 = 0.08 单位），用户不可感知。但与 boundaryHint 明确的"[存在]态下输入不产生位移"语义不一致。

**SR-1**（结算顺序）：✅ pass (95%) — 水平位移 L58 → 重力 L64-66 → 合成 L70，顺序正确

**修复建议**：在 `Tick()` 开头加入 `if (_stateMachine.Current == PlayerState.Idle && !intent.JumpPressed) return;` 或在位移计算前检查状态

**违规证据**：

- Grep `jumpBuffer|inputBuffer|preJump|jumpQueued|earlyJump` → **0 命中**
- 搜索范围覆盖 `.cs` / `.yaml` / `.asset` 全格式
- 跳跃条件硬编码为 `intent.JumpPressed && _stateMachine.IsGrounded`（PlayerMovementPipeline.cs L60），无任何窗口容差

**SR-1**（当帧起跳）：✅ pass (85%) — `GetKeyDown(Space)` 在 InputAdapter.Poll() 同帧传递到 Pipeline.Tick() 的跳跃赋值

**影响评估**：中。土狼时间和预输入缓冲是 spec 文档 D slice-1 落地三件套 B2 + I4 跳跃规则异常路 2/3 的明确要求，属于**功能缺失**而非退化。

**修复建议**：

2. 在 `PlayerMovementPipeline` 中增加 `_coyoteTimer` / `_jumpBufferTimer` 计时器
3. 修改跳跃条件为 `(intent.JumpPressed || _jumpBufferTimer > 0) && (_stateMachine.IsGrounded || _coyoteTimer > 0)`

### ❌ F3. qc-1778609400007 — 镜头跟随（SR-1 FAIL）

**契约规则**：第三人称硬跟模式——方块移动时镜头即时跟随，**不做弹簧/阻尼平滑**

**违规证据**：
- Grep `SmoothDamp` → **OrbitCamera.cs:102 命中**：
  ```csharp
  _smoothPivot = Vector3.SmoothDamp(_smoothPivot, desiredPivot, ref _pivotVelocity, followSmoothTime);
  ```
- `followSmoothTime = 0.15f`，属于典型阻尼平滑参数
- SR-1 为 `grep_forbidden` 类型：关键词命中即判 FAIL，无需语义分析

**注意**：`AlienStarBootstrap.UpdateFallbackCamera()` L192-204 **IS** 硬跟（`cam.transform.position = lookTarget + offset`，无任何平滑），但 OrbitCamera 是默认启用的主摄像机，fallback 仅在 OrbitCamera 异常时启用。

**SR-2**（垂直跟随）：✅ pass (85%) — OrbitCamera.UpdatePivot() 追踪 target.position.y

**SR-3**（防穿透推近）：✅ pass (85%) — HandleObstruction() L106-135 探测体素遮挡并推近

**影响评估**：中。OrbitCamera 是 slice-2 的自由轨道摄像机升级，超出 slice-1 "硬跟"规格。当前 `followSmoothTime=0.15f` 虽然很短，但与 spec "不做弹簧/阻尼平滑" 的字面要求矛盾。

**修复建议**：方案二选一：
- A) 将 `followSmoothTime` 设为 0 或直接用 `_smoothPivot = desiredPivot` 替换 SmoothDamp 调用
- B) 在 spec 中明确豁免 OrbitCamera 的 SmoothDamp（属于 slice-2 特性的提前引入）

### ❌ F4. qc-1778609400011 — 碰撞查询服务（SR-3 FAIL）

**契约规则**：查询坐标超出地图边界时不崩溃且返回 clamp 后结果

**违规证据**：
- Grep `Clamp|BoundsCheck|OutOfBounds|MapBoundary|ClampPosition` in VoxelCollisionService.cs → **0 命中**
- `IsSolidAt()` L51: `_env.CheckCollision((Vector3d)position)` — 坐标原样透传
- `QueryGround()` L67-93: 多点射线检测，采样坐标无边界校验
- `QueryCollision()` L120-185: 六面 IsSolid 检测，坐标均无 clamp

**SR-1**（solid 阻挡）：✅ pass (90%) — IsSolidAt 正确委托 CheckCollision

**SR-2**（air 可通过）：✅ pass (85%) — !IsSolidAt 时不阻挡

**SR-4**（不可用信号）：✅ pass (90%) — IsServiceAvailable 属性 + 各方法入口守卫

**影响评估**：中-高。VoxelPlay 引擎内部**可能**有边界处理，但 E 层未做显式防护。若引擎更新或配置变更导致边界行为改变，可能引发异常。

**修复建议**：在 VoxelCollisionService 三个公开方法入口处增加坐标 clamp：
```csharp
private Vector3 ClampToWorldBounds(Vector3 pos) {
    // 从 VoxelPlayEnvironment 获取世界边界
    return new Vector3(
        Mathf.Clamp(pos.x, _worldMin.x, _worldMax.x),
        Mathf.Clamp(pos.y, _worldMin.y, _worldMax.y),
        Mathf.Clamp(pos.z, _worldMin.z, _worldMax.z));
}
```
